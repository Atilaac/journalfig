# Specifications

Every number in the themes is read from a publisher document. The pages below record which document, which
edition, and the date the numbers were last checked against it — a specification is only as trustworthy as
that date, because publishers revise their artwork guidelines without notice.

If you find a value that no longer matches what the publisher states, please
[open a specification correction](https://github.com/Atilaac/journalfig/issues/new?template=spec_correction.yml).

## Derived values

APS publishes only the single-column width (8.5 cm / 3 3/8 in). The 1.5- and 2-column values are derived
from standard REVTeX two-column geometry — 7.0 in text width with a 0.25 in gutter — and are the only
inferred numbers in the package. They are marked `DERIVED` in `_specs.py`.

## Choices the package makes

**One check is not a publisher's requirement.** The `vector` rule fires when an un-rasterized artist
holds more than `jf.VECTOR_ELEMENT_LIMIT` elements, because a figure like that produces a file large
enough to be refused by a submission system. No publisher document states a path-count limit; this is
the package's own judgement, and it is the only rule here that is not traceable to a source.

**Every theme writes PDF, SVG and PNG.** Publishers differ on what they accept, but the useful set on disk
is the same everywhere: one file to submit, one to edit, one to show. Anything else is available through
`jf.save(fig, path, formats=[...])`.

**Accepted-as-final-artwork lists are conservative.** They record what this package has read in the
publisher's own document, not everything the publisher might take. Elsevier's list comes from its
[artwork formats checklist](https://www.elsevier.com/about/policies-and-standards/author/artwork-and-media-instructions/artwork-formats-checklist)
("EPS, PDF, TIFF or JPEG"); the Nature and APS lists have not been verified beyond the formats named in
their sizing documents, so an unexpected draft warning there is worth
[reporting](https://github.com/Atilaac/journalfig/issues/new?template=spec_correction.yml) rather than
working around.

**No theme writes EPS by default.** APS documents `.eps` for colour-online-only figures and Elsevier names
it for vector artwork, so both accept it — but the PostScript backend cannot express transparency: any
artist with `alpha < 1` is silently flattened to opaque, so the EPS stops agreeing with the PDF of the same
figure. PDF, SVG, PNG and TIFF all preserve it.

**TIFFs are LZW-compressed**, which takes a single-column Elsevier figure from 7.8 MB to 132 kB with
byte-identical pixels. Elsevier recommends TIFF but documents no compression scheme either way, so this is
the package's choice, not theirs — `jf.save(fig, path, pil_kwargs={})` writes it uncompressed.
